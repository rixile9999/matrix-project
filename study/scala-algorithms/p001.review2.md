핵심 설계는 완전히 잡았다! 현재 연속 길이(`acc`)와 지금까지의 최댓값(`lgt`)을 꼬리 재귀로 한 번만 훑는 O(n) 시간 / O(1) 공간 풀이이고, 문제 표의 세 예시(`Array(2, 5, 0, 3, 4, 1, -2)`, `Array(-1, 0, -3)`, `Array.empty[Int]`)는 모두 통과했다.

다만 **배열이 양수로 끝나는 경우**에 실패한다:
- `Array(1, 2, 3)` → 기대값 `3`, 실제 반환 `0`
- `Array(2, 0, 3, 4, 5)` → 기대값 `3`, 실제 반환 `1`
- `Array(5)` → 기대값 `1`, 실제 반환 `0`

`nums(i) <= 0`을 만났을 때만 `lgt`를 갱신하기 때문에, 마지막에 진행 중이던 `acc`가 `lgt`와 비교되지 않은 채 `i == nums.size`에서 끝나 버린다. 한 곳만 손보면 바로 통과다. `p001.answer3.md`에 고쳐서 다시 내 보자. (하위 문제는 필요 없는 단순 실수다.)

Great core design: O(n) time / O(1) space tail recursion tracking both the current run (`acc`) and the best run (`lgt`), passing all three table examples.

However, it fails whenever **the longest run ends at the end of the array**:
- `Array(1, 2, 3)` → expected `3`, got `0`
- `Array(2, 0, 3, 4, 5)` → expected `3`, got `1`
- `Array(5)` → expected `1`, got `0`

Because `lgt` is only updated when `nums(i) <= 0`, the final in-progress `acc` is never compared with `lgt` when `i == nums.size` is reached. Fix that and submit in `p001.answer3.md`.
