## 2. 틀렸거나 막혔던 지점 & 체크리스트

### (1) `foldLeft` 안에서 조기 종료(`return`)와 누적 대상 혼동 (`p001.1`, `gap`)
- **문제**:
  - 양수의 **개수**를 세야 하는데 `acc + x`로 **값의 합**을 더함 (`Array(4, 2, 0, 8)` → `2` 대신 `6`).
  - `foldLeft` 람다 안에서 `return acc`를 사용 → Scala 3에서 비지역(non-local) `return`은 폐지/경고 대상이며, `foldLeft`는 끝까지 순회하는 연산이라 조기 종료에 맞지 않음.
- **기억할 점**:
  - 조건이 깨질 때 중간에 멈춰야 하면 `foldLeft` 대신 **내부 꼬리 재귀**, **`while`**, **`boundary`/`break`**, 또는 **`takeWhile`/`prefixLength`/`indexWhere`**를 쓴다.
  - 누적기가 "개수(+1)"인지 "합(+x)"인지 먼저 확인.

### (2) 배열 범위 검사 누락 (`p001.1.1`, `slip`)
- **문제**: `if nums(i) <= 0 then ...`만 검사하고 `i == nums.size` 검사를 빼먹어, 전부 양수(`Array(1, 2, 3)`)거나 빈 배열(`Array.empty[Int]`)에서 `ArrayIndexOutOfBoundsException` 발생.
- **기억할 점**:
  - 인덱싱 전에 **반드시 `i == nums.size`를 왼쪽에** 둔다 (`||` 단락 평가 덕분에 범위 끝이면 `nums(i)`를 평가하지 않음):
    ```scala
    if i == nums.size || nums(i) <= 0 then ...
    ```
  - 테스트할 때 **빈 배열**, **전부 조건 통과**, **첫 원소부터 실패** 3가지는 항상 돌려본다.

### (3) 연속 구간 최댓값의 끝처리 & 증가 전 비교 (`p001`, `slip` × 2)
- **문제 1 (끝 구간 누락)**: `nums(i) <= 0`을 만났을 때만 `lgt`를 갱신하면, 배열이 양수로 끝날 때(`Array(1, 2, 3)`, `Array(2, 0, 3, 4, 5)`, `Array(5)`) 마지막 `acc`가 `lgt`에 반영되지 않고 버려짐.
- **문제 2 (off-by-one)**: 양수 분기에서 `acc`를 `acc + 1`로 늘리면서 `lgt`를 **늘어나기 전 `acc`**와 비교해 최댓값이 1 모자람 (`Array(1, 2, 3)` → `2`, `Array(5)` → `0`).
- **기억할 점**:
  - 둘 중 한 방식으로 일관되게 처리한다:
    1. **매 양수마다 갱신**: `val next = acc + 1; parse(lgt.max(next), next, i + 1)` (그러면 `nums(i) <= 0`이나 종료 시점에 다시 비교할 필요 없음).
    2. **끊길 때 + 종료 시점에 갱신**: `if i == nums.size then lgt.max(acc) ...`.

### (4) 함수 시그니처 감추기 & `@annotation.tailrec` (`p001.1.1.1`, `p001`)
- 재귀용 상태 변수(`i`, `acc`, `lgt`)를 공개 함수의 기본 인자(`i: Int = 0`)로 빼면 시그니처가 바뀌고 외부에서 잘못된 값을 넘길 수 있다.
- **내부 헬퍼 함수(`def loop(...)`)**로 감추고 위에 `@annotation.tailrec`을 붙이면 원래 시그니처를 지키면서 100,000개 입력에서도 스택 안전성이 보장된다.

## 3. 오늘 한 질문과 핵심 답변

### Q1. 꼬리 재귀 말고 반복/조기 종료하는 방법?
`firstNonPositiveIndex` 기준 3가지 대안:
1. **지역 `var` + `while` 루프** — 함수 내부 지역 가변 상태는 스칼라에서도 흔하고 빠르다(컴파일러가 꼬리 재귀도 `while`로 변환함):
   ```scala
   def firstNonPositiveIndex(nums: Array[Int]): Int =
     var i = 0
     while i < nums.length && nums(i) > 0 do i += 1
     i
   ```
2. **표준 컬렉션 메서드**:
   - 첫 위치 찾기: `nums.indexWhere(_ <= 0)` (없으면 `-1` 반환)
   - 앞부분 조건 만족 원소 자르기: `nums.takeWhile(_ > 0)`
   - 앞부분 조건 만족 길이: `nums.prefixLength(_ > 0)`
3. **Scala 3 `boundary` / `break`** — `for`나 고차 함수 안에서 안전하게 조기 종료:
   ```scala
   import scala.util.boundary, boundary.break

   boundary:
     for i <- nums.indices do
       if nums(i) <= 0 then break(i)
     nums.length
   ```

### Q2. `Array`를 앞에서부터 `0..n` 부분만 잘라 새 배열 만들기?
둘 다 새 `Array`를 반환하고 범위를 벗어나도 예외 없이 안전하게 잘린다.
- `arr.take(n)` — 앞에서 최대 `n`개 (인덱스 `0` ~ `n - 1`)
- `arr.slice(from, until)` — `from` 포함, `until` **미포함** (`arr.slice(0, n)` == `arr.take(n)`)
- 인덱스 `n`을 **포함**하려면 `take(n + 1)` 또는 `slice(0, n + 1)`.

### Q3. Scala에서 삼항 연산자(`cond ? a : b`) 지원하나?
- **미지원**. `if ... then ... else ...` 자체가 값을 반환하는 식(expression)이라 삼항 연산자를 그대로 대신한다:
  ```scala
  val x = if a > b then a else b
  ```
- 두 숫자 중 큰 값은 `a.max(b)` 또는 `math.max(a, b)`가 더 간결하다.

## 4. 오늘 다룬 핵심 CS / 스칼라 전문 개념

| 개념 (영문) | 핵심 설명 | 오늘 코드와의 연결 |
|---|---|---|
| **꼬리 재귀 & 꼬리 호출 최적화**<br>(Tail Recursion & Tail Call Optimization, TCO) | 재귀 호출이 함수의 **맨 마지막 동작**일 때, 컴파일러가 호출 스택을 새로 쌓지 않고 내부적으로 `while` 루프로 변환해 O(1) 스택 공간으로 실행하는 최적화. | `p001`에서 100,000개 배열을 스택 오버플로 없이 통과. Scala에서는 `@annotation.tailrec`으로 최적화 가능 여부를 컴파일 타임에 검증한다. |
| **단락 평가**<br>(Short-Circuit Evaluation) | 논리 연산 `A \|\| B`에서 `A`가 `true`이면 `B`를 평가하지 않고, `A && B`에서 `A`가 `false`이면 `B`를 평가하지 않는 규칙. | `i == nums.size \|\| nums(i) <= 0`에서 경계 체크를 왼쪽에 두어 `ArrayIndexOutOfBoundsException`을 방지(`p001.1.1`, `p001.1`). |
| **반열린 구간**<br>(Half-Open Interval, `[from, until)`) | 시작 인덱스는 포함하고 끝 인덱스는 제외하는 구간 표기. 길이가 항상 `until - from`과 일치해 빈 구간 `[0, 0)`과 경계 처리가 깔끔하다. | `nums.slice(0, i)`와 `nums.take(i)` 모두 `[0, i)` 구간을 자른다. |
| **경계값 오류 / 하나 차이 오류**<br>(Off-by-One Error) | 인덱스, 구간 끝, 갱신 타이밍에서 딱 1만큼 어긋나는 대표적인 버그. | `p001` 3차 시도에서 `acc`를 `acc + 1`로 늘리기 전 값과 `lgt`를 비교해 답이 1 모자랐던 실수. |
| **루프 불변식**<br>(Loop Invariant) | 반복(또는 재귀 호출)의 매 단계 시작·끝에서 **항상 참으로 유지되는 조건**. 불변식을 명확히 세우면 끝처리 버그가 줄어든다. | `p001` 4차 시도에서 "`lgt`는 지금까지 본 구간 길이의 최댓값(`lgt >= acc`)"이라는 불변식을 매 양수마다 유지하자, 종료 시점에 추가 비교 없이 `lgt`만 반환해도 정확해졌다. |
| **비지역 반환**<br>(Non-local Return) | 고차 함수 안의 람다(`foldLeft` 등)에서 바깥쪽 함수를 즉시 빠져나가려는 `return`. JVM에서 내부적으로 예외를 던져 제어 흐름을 꺾는 비용·위험 때문에 Scala 3에서 폐지(deprecated)되었다. | `p001.1` 첫 시도에서 `foldLeft` 안의 `return acc`가 경고를 낸 이유. Scala 3에서는 대신 `scala.util.boundary` / `break`를 사용한다. |
| **식 중심 언어**<br>(Expression-Oriented Language) | `if/else`, `match`, 블록 등이 실행만 하는 문장(statement)이 아니라 **값을 계산해 반환하는 식(expression)**인 언어 설계. | Scala에 별도의 삼항 연산자(`? :`)가 필요 없는 이유 (`if a > b then a else b` 자체가 값). |
| **단일 패스 선형 스캔**<br>(Single-Pass Linear Scan / O(n) Time, O(1) Space) | 배열을 앞에서 뒤로 한 번만 훑으면서, 현재 구간 상태(`acc`)와 전체 최적값(`lgt`)처럼 고정 개수의 상태 변수만 유지하는 알고리즘 패턴(카데인 알고리즘 등의 기초). | `p001` 최종 풀이가 중간 배열 생성 없이 최대 100,000개 입력을 선형 시간에 처리한 구조. |
