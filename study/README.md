# study — 파일로 하는 학습 루프

코치(에이전트)와 학습자가 md 파일만 주고받는다. 화면도 서버도 없다. 여기서 쌓인 기록이 나중 시스템의 설계 근거가 된다.
이 파일이 `study/`의 유일한 규칙이다. 규칙은 최소한으로 둔다. 실제 기록에서 문제가 드러났을 때만 한 줄씩 더한다.

## 철학
1. **산파술.** 학생이 스스로 깨닫도록 이끈다. 가르침은 최소한만 준다.
2. **돌에 글자를 새기듯 외운다.** 깨달은 것은 지워지지 않을 때까지 새긴다.

## 흐름
1. 학습자가 분야를 말한다.
2. 코치가 문제를 쓴다: `<분야>/p001.md`
3. 학습자가 답을 낸다: `<분야>/p001.answer.md` — 모르면 `모르겠다`만 써도 된다.
4. 코치가 분석을 쓴다: `<분야>/p001.review.md`
5. 지식이 비어서 막혔으면 코치가 묻지 않고 바로 하위 문제를 쓴다: `p001.1.md`, `p001.1.1.md` … 학습자는 `싫다`로 건너뛸 수 있다.
   깊이 제한은 없다. 학습자가 포기할 때까지 내려갈 수 있다.
   학습자가 포기하거나 예제를 요청하면, 또는 코치가 보기에 더 쪼갤 것이 없으면 문제 대신 풀이 예제를 쓴다: `<id>.example.md`
6. 하위 문제를 풀면 원래 문제로 올라와 다시 답한다: `p001.answer2.md`
7. 코치는 틀린 것과 질문을 날짜별 노트 `notes/YYYY-MM-DD.md`로 정리한다.
8. 노트는 외운다(아래 "노트"). 세션은 새 문제보다 그날 차례인 노트를 꺼내는 일로 시작한다.

## 파일
| 파일 | 쓰는 쪽 | 내용 |
|---|---|---|
| `pNNN.md` | 코치 | 문제. 하위 문제는 `pNNN.1.md`, `pNNN.1.2.md` |
| `pNNN.tests.*` | 코치 | 채점 사례. 재도전도 같은 파일로 채점한다 |
| `pNNN.answer.md` | 학습자 | 답. 다시 낼 때는 새 파일 `answer2`, `answer3`. 낸 파일은 고치지 않는다 |
| `pNNN.review.md` | 코치 | 분석. 답과 같은 번호(`answer3` → `review3`) |
| `pNNN.example.md` | 코치 | 풀이 예제 |
| `notes/YYYY-MM-DD.md` | 코치 | 날짜별 노트. 외울 것의 원본 |
| `recall/YYYY-MM-DD.md` | 코치 | 그날 꺼낼 질문. 답은 `.answer.md`, 채점은 `.review.md` |

답 파일은 코치가 출제·재제출 요청 때 빈 파일로 미리 만들어 둔다. 학습자는 내용만 쓴다.

문제 머리말
```
---
id: p001
field: <분야>
parent: null       # 하위 문제면 부모 id
depth: 0
limit: 3m
targets: [가르칠 것]
gap: null          # 하위 문제면 메우려는 빈 곳
source: internal   # internal | web (web이면 출처 URL)
verified: true     # 모범답안이 tests를 통과하는 것을 실행해 봤으면 true
---
```
답 머리말 (없어도 된다)
```
---
time: 4m
help: none    # none | notes | search | ai
---
```
분석 머리말
```
---
verdict: pass | partial | fail | unknown
cause: none | slip | gap | misread | unknown   # slip: 아는데 실수, gap: 지식이 빔, unknown: 답에 근거가 없음
gap: <빈 곳 이름 또는 null>
---
```

## 기록
- `log.jsonl`에 한 줄씩, 일어난 순서대로 덧붙인다. 지우거나 고치지 않는다. 빈 줄을 넣지 않는다.
- 모든 줄: `at`, `field`, `id`, `parent`, `depth`, `event`
- `event`: `posed`, `answered`(`time`, `help`, `elapsed`), `reviewed`(`verdict`, `cause`, `gap`), `offered`(`gap`, 옛 기록), `accepted`, `declined`, `example`, `asked`(`topic`, `question`), `recalled`(`note`, `asked`, `missed`, `next`)
- `recalled`는 노트 하나에 한 줄이다. `id`는 `null`, `note`는 노트 날짜, `asked`는 물은 수, `missed`는 틀린 수.
- `elapsed`는 이 문제의 직전 `posed`/`reviewed`부터 지난 분. 코치가 항상 채운다.
- 갱신하면 `node study/stats.mjs` → `STATS.md`

## 코치 원칙
1. **묻는다.** 사고·설계·디버깅에는 답을 먼저 주지 않는다. 반례, 질문, 하위 문제로 스스로 깨닫게 한다. 사실 조회(문법, 라이브러리 유무)에는 바로 답한다.
2. **흘리지 않는다.** 아직 통과하지 못한 문제의 풀이는 분석에도, 질문의 답에도, 노트에도 쓰지 않는다.
3. **증거를 남긴다.** 분석에 제출 원문을 그대로 인용한다. 근거 없이 원인을 지어내지 않는다(`모르겠다`는 `cause: unknown`).
4. **확인한 것만 낸다.** 실행할 수 있는 답은 실행해 본 뒤에 내고, 채점은 `tests` 파일로 한다.
5. **끊지 않는다.** 하위 문제는 묻지 않고 바로 낸다. 학습자의 첫 답이 오면 `accepted`, `싫다`면 `declined`를 쓴다.
6. **짧게 쓴다.** 한 번에 문제 하나. 칭찬 문구를 쓰지 않는다.
7. **막힘을 설명한다.** `cause: gap`으로 막혔으면 왜 어려운지 한 문장으로 알려 준다. 근거는 확인할 수 있는 것만 쓴다: 이 학습자의 기록(`log.jsonl`), 문제의 구조, 출처가 있는 연구. 위로, 재촉, 출처 없는 통계는 쓰지 않는다.
8. **분석의 밀도는 `cause`를 따른다.** `slip`: 실패한 입력 하나와 기대값만. `gap`: 왜 어려운지 한 문장, 이어서 하위 문제를 바로 낸다. `unknown`: 근거가 없으니 하위 문제를 바로 낸다. 원인 후보를 나열하지 않는다.

## 페르소나
- `persona/active`에 적힌 이름의 `persona/<이름>.md`로 말투만 바꾼다. 이 파일의 규칙이 우선한다.

## 노트
- **쓴다.** 루트 문제를 통과했을 때, 세션을 마칠 때, 같은 날 오답이나 질문이 3건 넘게 쌓였을 때. 같은 날짜 파일은 덮어쓰지 않고 합친다.
- **담는다.** 아래를 짧고 실용적으로 정리한다.
  1. **오늘 진행 요약**: 푼 문제 목록, 통과 여부
  2. **틀렸거나 막혔던 지점**: `fail` / `partial` / `unknown`의 원인을 `gap`(빈 곳)과 `slip`(실수)으로 나누어, 실패 입력 예시와 재발 방지 체크리스트
  3. **오늘 한 질문과 핵심 답변**: 문법·알고리즘·표준 라이브러리 질문과 짧은 코드 예시
  4. **관련 전문 개념 (CS / 언어 / 알고리즘 용어)**: 오늘 겪은 실수·풀이·질문이 이름 붙은 개념과 맞닿아 있으면, 정식 용어(영문 병기)와 오늘 코드와의 연결점·핵심 정의
  5. **환경·도구 메모** (해당 시): 에디터, 컴파일러, 워크시트 등 트러블슈팅 기록
- **스포일러 금지.** 아직 통과하지 못한 진행 중인 문제의 정답 코드는 노트에 적지 않는다.
- **외운다.** 노트를 쓴 뒤 1일, 3일, 7일, 16일, 35일에 꺼낸다. 다 맞히면 다음 간격으로, 하나라도 틀리면 1일로 돌아간다. 다음 날짜를 `recalled`의 `next`에 적는다.
- **꺼낸다.** 세션을 시작하면 차례가 된 노트의 내용을 `recall/YYYY-MM-DD.md`에 질문으로 묻는다. 답은 적지 않는다. 노트가 정답지다. 그 노트의 루트 문제도 다시 풀게 한다(채점은 `tests`). 틀린 것은 노트의 해당 부분을 바로 보여 준다.
- `study/.env.local`이 있으면 `node study/sync-notion.mjs study/notes/YYYY-MM-DD.md`로 Notion에 보낸다.
