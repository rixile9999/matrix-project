# Debrief drills — generated variations for a note

Status: in implementation (2026-11-27). Contract for the three work packages below.

## What it does
A Debrief note (a mistake pattern that reached the note threshold) gets machine-verified **trace exercises** generated by a model
("drills"). The learner adds a drill to the memo deck; from then on it is reviewed by the existing memo schedule as check `drill-<id>`.

Flow: note → generate (model A) → machine verification (Scala run) → review (model B) → stored `ready` → learner adds → memo review.

Rules
- Only notes (`PatternStat.note === true`) get drills. Scala only.
- Nothing unverified is stored (project rule 18). A drill that fails any check is discarded silently and counted in the job row.
- Generation runs together with the note by default (`drillAuto` is on unless the learner turned it off): when a session ends, every note pattern hit in it gets drills, in one sequential background job. It needs a connected backend on the account; without one nothing happens. A pattern whose last auto job kept nothing is skipped for 24 h. Adding to the deck is always the learner's choice (rule 25).
- Caps: `PER_JOB = 3` drills asked per job, `PER_NOTE = 6` non-dropped drills per pattern, `PER_DAY = 9` stored drills per account per local day.
- UI text follows rule G in CLAUDE.md: chic, minimal, no explanations. Exception: one short notice that records are sent to the model provider.
- All UI and stored text is bilingual (`t('한국어','English')` in components, `tr(...)` on the server).

## Drill shape (core/drill.ts)
```ts
export type Bi = { ko: string; en: string };
export type Drill = {
	code: string;              // what the learner reads; 1–8 lines, <= 400 chars, no comments
	verify: string;            // code with exactly one `// => value` line (cheat-sheet format); value === options[0].text.ko === .en unless it is prose
	prompt: Bi;                // one short line, must not reveal the answer
	options: { text: Bi; why: Bi }[]; // exactly 4, options[0] is correct, texts distinct per locale
	slip: string | null;       // for compile patterns: a variant of `code` that makes this very mistake and must NOT compile
};
```
- The correct option is always a value produced by running `verify` (never "compile error").
- A wrong option may be the text `컴파일 오류` / `Compile error`.
- `slip` is required when the pattern's `on === 'compile'`, null otherwise.

## core/drill.ts (pure, no I/O) — package A
```ts
export const PER_JOB = 3, PER_NOTE = 6, PER_DAY = 9;
export type DrillInput = {
	pattern: { id: string; title: Bi; rule: { ko: string[]; en: string[] }; on: 'compile' | 'failed' };
	exemplar: { code: string; verify: string; prompt: string; options: { text: string; why: string }[] } | null; // the catalog check, as a format example
	evidence: { code: string; message: string }[]; // up to 3 of the learner's own failing lines
	existing: string[];        // code of drills that already exist for this pattern (do not repeat)
	count: number;
};
export const DRILL_SYSTEM: string;                       // English system prompt; demands a single JSON object {"drills":[...]}
export function drillPrompt(input: DrillInput): string;  // JSON.stringify of the input plus nothing else
export function parseDrills(reply: string, input: DrillInput): Drill[]; // tolerant JSON extraction (```json fences, leading prose); drops invalid items; [] when nothing valid
export function drillHash(code: string): string;         // sha256 hex of whitespace-normalised code (node:crypto is fine in core? NO — use a pure JS hash (e.g. FNV-1a 64 as hex) so core stays dependency-free)
export const REVIEW_SYSTEM: string;                      // reviewer gets drills WITHOUT knowing which option is correct... see below
export function reviewPrompt(drills: Drill[], seeds: string[]): string; // options shuffled deterministically per seed; reviewer must answer each
export function parseReview(reply: string, drills: Drill[], seeds: string[]): { index: number; ok: boolean; reason: string }[];
export function drillCheck(d: Drill, id: number, patternId: string, topic: string, locale: 'ko' | 'en'): TraceCheck; // id `drill-<id>`, debrief: patternId, answer 0, unlock []
```
Validation in `parseDrills` (each failure drops the item):
- shapes and length limits above; both locales non-empty; 4 options; distinct texts
- `verify` has exactly one `// => ` line and its value equals `options[0].text.ko` and `.en`
- every non-blank line of `code` appears (trimmed, with the `// =>` part removed) in `verify`
- prompt does not contain the correct value as a whole token
- `drillHash(code)` not in `existing` hashes, not equal to the exemplar's code, no duplicates within the reply
- `slip` present iff compile pattern; `slip !== code`

Review: the reviewer model solves each drill blind (shuffled options, no `why`, no marked answer) and returns
`{"reviews":[{"index":0,"answer":2,"ambiguous":false,"reason":"…"}]}`. A drill is `ok` only if the reviewer's answer maps to option 0
and `ambiguous` is false. Missing or malformed review entries are `ok: false`.

Tests (`core/drill.test.ts`): parse happy path, each validation rule, fenced/prose-wrapped replies, review mapping with shuffles, drillCheck shape.

## server/drill.ts — package B
Tables (add to `server/db.ts` beside the other `debrief_*` tables, same style):
```sql
CREATE TABLE IF NOT EXISTS debrief_drills (id INTEGER PRIMARY KEY AUTOINCREMENT, pattern_id TEXT NOT NULL, created_at INTEGER NOT NULL,
  backend TEXT NOT NULL, reviewer TEXT NOT NULL, hash TEXT NOT NULL, body TEXT NOT NULL, state TEXT NOT NULL DEFAULT 'ready', state_at INTEGER);
CREATE UNIQUE INDEX IF NOT EXISTS debrief_drills_hash ON debrief_drills(pattern_id, hash);
CREATE TABLE IF NOT EXISTS debrief_drill_jobs (id INTEGER PRIMARY KEY AUTOINCREMENT, pattern_id TEXT NOT NULL, started_at INTEGER NOT NULL, ended_at INTEGER,
  process_id TEXT NOT NULL, backend TEXT NOT NULL, status TEXT NOT NULL, asked INTEGER NOT NULL DEFAULT 0, kept INTEGER NOT NULL DEFAULT 0, error TEXT);
CREATE TABLE IF NOT EXISTS debrief_drill_auto (id INTEGER PRIMARY KEY AUTOINCREMENT, at INTEGER NOT NULL, enabled INTEGER NOT NULL);
```
`state`: `ready | added | dropped`. `body` = JSON of `Drill`. Jobs from another `process_id` that are still `running` are marked `failed` (same idea as `pdf-jobs.ts`).

Exports
```ts
export type RunScala = (files: Record<string, string>) => Promise<{ stdout: string; stderr: string; code: number; timedOut: boolean }>;
/** Machine verification of one drill. Injectable runner so a script can use a local scala-cli. */
export async function verifyDrill(d: Drill, pattern: DebriefPattern, cat: DebriefPattern[], run: RunScala): Promise<{ ok: true } | { ok: false; reason: string }>;
export function drillsFor(patternId: string, locale): DebriefDrill[];       // non-dropped, newest first
export function drillJobState(patternId: string): 'running' | 'failed' | null; // latest job; 'failed' only if no later success
export function drillAuto(): boolean;
export function setDrillAuto(on: unknown): DebriefOk;
export function startDrills(pattern: unknown, backend?: unknown): { status: number; body: DebriefOk }; // validates note + caps, inserts job, `void run(...)`, returns 202-ish { ok: true }
export function setDrillState(id: unknown, drop: unknown): DebriefOk;        // add: also inserts the pattern into debrief_deck if missing
export function deckDrillChecks(locale): TraceCheck[];                       // drills in state 'added' as memo checks
export function autoDrills(problemId: string): void;                         // if drillAuto(): for each note pattern hit in this problem's latest finished session and under caps, startDrills(...)
```
`verifyDrill`
1. Run `verify` with the cheat-sheet harness (`cheatsheet/_harness/Cheat.scala`, `annotatedBody`, `parseShows` from `scala-run.ts`): it must compile, not time out, and the shown value must equal `options[0].text.ko`.
2. No wrong option text equals the shown value.
3. Compile patterns: run `slip` as `User.scala` wrapped the way a learner submission is compiled (see `judge.ts` for how compiler errors are cleaned into the `User.scala:L:C` form that `parseCompile`/`matchCompile` in `core/debrief.ts` expect). It must fail to compile, and the FIRST matching catalog pattern must be this pattern.
4. `failed` patterns: skip step 3.

Job (`run`): build `DrillInput` from the catalog, the note's evidence, and existing drills → `askCoach(generator)` → `parseDrills` → `verifyDrill` each →
`askCoach(reviewer)` with `reviewPrompt` → keep `ok` → insert (respect caps and the unique hash) → finish job row. One repair retry of the generation
call when nothing parses (same idea as `checkedReply` in `pdf-generate.ts`). Generator = requested backend or `DEFAULT_BACKEND` from `server/debrief.ts`;
reviewer = another connected backend when one exists (`connectedCoaches()`), else the same. Keep the account context (AsyncLocalStorage) alive like `pdf-jobs.ts`.
Errors never throw to the caller; they land in the job row.

Wiring
- `server/memo.ts` `world()`: append `deckDrillChecks(locale)` to `checks` (after the file checks; no id collisions since ids start with `drill-`).
- `server/debrief.ts` `notes()`: fill `drills` and `drillJob`; `debriefData`: `drillAuto`. For patterns that are not notes: `drills: [], drillJob: null`.
- `server/lang.ts`: where a session becomes finished in `runCode` / `revealSolution`, call `autoDrills(problemId)` inside try/catch (must never break a run).
- Routes: `src/routes/debrief/drills/+server.ts`, `drills/add/+server.ts`, `drills/auto/+server.ts` — copy the style of `src/routes/debrief/deck/+server.ts`.
- Tests: `server/drill.test.ts` for `verifyDrill` with a fake runner (pass, wrong value, slip compiles, slip classified as another pattern) and state transitions with a temp DB (see how `server/garden.test.ts` or `server/coach.test.ts` set up an account DB).

## UI — package C
`src/lib/debrief/NoteView.svelte` gets a "변형 / Variations" block under the note's own check:
- each drill: prompt + code (no options, no answer), a small state button: `덱에 넣기 / Add` ↔ `덱에 있음 / In deck`, and a quiet `×` to drop
- a `만들기 / Make` button (disabled while `drillJob === 'running'`, shows a pulse then); `drillJob === 'failed'` shows `실패 · 다시 / Failed · retry`
- while running, poll with `invalidateAll()` every 4 s; stop when not running
- one notice line under the button: `만들면 이 노트의 기록이 선택한 모델 제공자에게 전송됩니다.` / `Making sends this note's records to the selected model provider.`
`src/routes/debrief/+page.svelte`: one quiet toggle near the 패턴 heading: `자동 / Auto` (`aria-pressed`, posts `/debrief/drills/auto`).
Types are already in `src/lib/types.ts` (`DebriefDrill`, `DebriefNote.drills`, `DebriefNote.drillJob`, `DebriefData.drillAuto`).
