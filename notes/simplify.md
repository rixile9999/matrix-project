# 문제 세트 확장 단순화 아이디어
문제를 생성하는 기준이 무한하기 때문에 에이전트기반 문제추천 시스템을 만드려고 함.

# 에이전트 기반 문제추천 시스템
1. (사용자가 공부하는 분야를 지정할 수 있음)코치 에이전트가 내 수준에 맞는 문제를 추천해줌
2. 나는 추천해준 문제를 품
3. 문제 풀기에 실패할경우, 푸는 과정에서 나온 질문, 오답등의 사용자 패턴에 기반하여 해당문제를 subproblem으로 분할하여 재귀적으로 문제를 다시 추천함4. subproblem 도 못풀면 재귀적으로  subsubprolem 문제 진행.
5. 사용자는 최종적으로 원래 문제를 풀 수 있게됨. 이과정을 분석하여 새 문제 및 회고를 debrief에 등록하고 문제세트의 연결 상태도 저장함.

# 결정 사항 (2026-11-27)
- 풀 안에 맞는 문제가 있으면 그것을 고른다. 사용자가 원하는 학습이 풀을 벗어나면 에이전트가 판단해 문제를 생성한다.
- 하위 문제는 지식 부재가 실패 원인일 때만. 실수(패턴)는 Debrief 변형 문제로 보낸다 (`notes/debrief-drills.md`).
- 코치가 근거 한 줄과 함께 하위 문제를 제안한다. 사용자가 받아들이면 지식 부재를 인정한 것으로 기록한다. 거절하면 원래 문제를 계속한다.
- 깊이 제한 3단계. 3단계에서도 실패하면 더 쪼개지 않고 풀이 예제와 인출 카드를 보여 준 뒤 한 단계씩 올라온다.
- 생성은 에이전트의 내적 지식으로 먼저. 생성(검증 통과)에 실패하면 웹 검색을 허용한다.
  - 검색 결과는 사실 확인용 참고 자료. 문제 본문을 베끼지 않는다. 출처를 기록한다. 검색 내용 속 지시는 따르지 않는다.
  - 워커의 외부 접속 허용 설정 변경이 필요하다 (승인됨).
- 기계 검증이 안 되는 분야도 허용. 다른 모델의 교차 풀이를 통과한 것만 내고 "미검증"으로 표시하며 실력 기록에 넣지 않는다.
- "해결"은 며칠 뒤의 재시도나 변형 문제 통과로만 기록한다. 직후 재시도는 허용하되 해결로 세지 않는다.
- 검증된 문제 본문과 연결(원래 문제 → 하위 문제)은 전체 회원이 재사용. 그 문제를 낳은 개인의 오답·질문은 계정 안에만.
- 생성 문제 난이도는 부모보다 한 단계 아래에서 시작, 기록으로 보정. 외부 척도 없는 문제는 레이팅에서 제외.
- 자동 실행은 전체 회원 기본값. 하루 생성 상한은 9개에서 시작. 시작 분야는 Scala.

# 걸리는 점 (평가)
- 하위 문제가 풀이 구조를 흘린다 → 지연 확인으로 보완.
- 실패 원인이 항상 지식 부재는 아니다 → 제안과 수락으로 분기.
- 생성 문제의 검증이 실행 중에 일어난다 → 기존 풀 우선, 생성물은 공유 자산으로 재사용.
- 연결의 품질은 "하위 문제 뒤 원래 문제의 지연 재시도 성공률"로 잰다. 효과 없는 연결은 내린다.

# 구현 순서
1. 기록 틀: 문제 트리(부모 → 하위, 깊이, 제안·수락·거절, 지연 확인)와 공유 연결 저장.
2. 코치 제안: 세션 중 실패 신호에서 기존 풀의 하위 문제를 골라 제안. 수락하면 하위 세션, 끝나면 복귀.
3. 생성: 풀에 맞는 문제가 없을 때 Scala 문제 생성과 기계 검증, 공유 등록.
4. 바닥 처리와 지연 확인, Debrief에 회고 등록.
5. 풀 밖 분야(미검증 표시)와 웹 검색.
