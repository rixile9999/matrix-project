# 트레이닝 시스템
1. 개념 습득, 문제풀이, 암기가 효과적으로 어우어져야함. 개인 소견으로 이론, 실전(혹은 퍼즐), 암기는 상보관계에 있음. 외우다보면 이해되고 이해하다보면 외워지며, 문제를 풀다보면 외워지거나 이해됨.  
2. 짧은 호흡으로 전개되어야함. 난이도에 따라 시간을 길게주든 짧게주든 무조건 제한시간이 있어야함
3. ELO 스타일의 레이팅이 있으면 좋겠음. 또한 레이팅이 나의 실력을 객관화 시킬 수 있어야 함. 즉 내부시스템 레이팅이 외부플랫폼 레이팅으로 변환 가능하거나 견줄 수 있으면 좋음.

4. 암기, 혹은 문제풀이에 있어. 모바일에서도 스낵처럼 풀 수 있도록 별도의 창구가 있었으면 함.

**트레이닝의 목표는 스피드, 정확도, 깊이를 모두 올리는 것임**
트레이닝, 교육, 암기 싸이클에 있어서는 알려지거나 검증된 최신 이론이 있다면 적극 사용할것.
단순히 방법론을 고안하지만 말고, 배우는 사람의 동기부여, 몰입감을 올릴 수 있는 환경에 대한 조성까지도 고민해볼것 .

## 1. 요구사항 검토 (연구와 어긋나는 부분은 수정)

| 요구사항 | 판단 | 이유 / 수정안 |
|---|---|---|
| 체스 오프닝 암기 중심 | **수정** | 아마추어 구간에서는 전술 패턴 인식과 계산이 실력을 훨씬 많이 설명합니다. 오프닝은 "좁은 레퍼토리 + 수순보다 아이디어·폰 구조"로 시작하고, 레이팅이 오를수록 수순 암기의 비중을 늘립니다(프로 구간에서는 준비량이 실제 승부 요인). |
| 모든 문제에 제한시간 | **조건부 수용** | 인출·전술·풀이에는 문항 단위 제한시간을 둡니다. 새 개념을 처음 배울 때 시간 압박을 주면 부호화가 나빠지므로, 개념 학습은 **세션 단위 타임박스**로만 묶습니다. 깊이 훈련은 길게 줍니다(체스 계산 20–30분, 코딩 60–90분). |
| 내부 레이팅 → 외부 레이팅 변환 | **부분 수용** | 문제 난이도를 외부 데이터로 고정하면 "퍼즐/문제 레이팅" 척도는 그대로 맞출 수 있습니다. 하지만 퍼즐 레이팅 ≠ 실전 레이팅이므로, 실전 레이팅은 본인 대국·콘테스트 기록으로 회귀 보정한 **추정치 + 신뢰구간**으로만 보여줍니다. |
| 이론·실전·암기의 상보성 | **수용** | 인출 연습이 이해까지 강화한다는 연구(Karpicke & Blunt 2011)와 일치합니다. 시스템이 이 순환을 자동으로 돌리게 설계합니다(§3). |

## 2. 채택하는 학습 원리
1. **인출 연습** (Roediger & Karpicke 2006): 읽기보다 떠올리기. 모든 개념에는 인출 문항이 따라붙습니다.
2. **간격 반복 – FSRS**: 현재 공개 알고리즘 중 가장 정확합니다(Anki 23.10+ 기본 옵션). 목표 유지율은 90%입니다.
3. **교차 학습(interleaving)**: 주제를 섞어 출제해 "어떤 기법을 쓸지" 판별하는 능력을 훈련합니다. 새 개념 직후에만 짧게 묶음 연습을 합니다.
4. **풀이 예제 → 점진적 생략** (인지부하 이론): 초보는 예제 중심입니다. **전문성 역전 효과**에 따라 레벨이 오르면 바로 문제로 넘어가며, 이 전환은 레이팅이 자동으로 결정합니다.
5. **85% 규칙** (Wilson et al. 2019): 정답률이 약 85%일 때 학습 속도가 최대입니다. 출제 난이도를 사용자 레이팅보다 살짝 낮게 맞춰 이 구간을 유지합니다. (§6의 몰입과도 직결)
6. **의도적 연습**: 약점 태그 집중 연습 + 즉각 피드백. 연습 "양"보다 "타깃팅과 피드백 품질"을 중시합니다(Macnamara 2014 메타분석 반영).
7. **Woodpecker 방식**(체스 전술): 같은 세트를 회차마다 더 빠르게 반복해 패턴을 자동화합니다. 스피드 축을 담당합니다.

## 3. 훈련 사이클
```
[개념 5–10분: 설명 + 풀이 예제]
   ↓
[인출 카드 3–5장] ──FSRS──→ 간격 복습
   ↓
[교차 출제 문제, 제한시간] → 오답/느린 정답 → [원인 태그 분석] → 새 카드 생성
   ↓
[레이팅 갱신]
```
**스피드·정확도·깊이는 모드를 분리합니다.** 한 문항으로 셋을 같이 재면 서로 상쇄되기 때문입니다.
- **스피드**: 짧은 제한시간, 쉬운~중간 난이도, 반복 세트
- **정확도**: 오답 페널티를 크게 두고, 확신도를 함께 입력하는 보정 훈련
- **깊이**: 긴 제한시간. 풀기 전에 후보수 / 접근법·복잡도를 먼저 적게 합니다.

### 코딩
1. **알고리즘**: CF 태그 × 난이도로 출제, 가상 콘테스트를 정기적으로 치르고, 기법은 카드로 관리합니다.
2. **함수형**: 순수성·불변성·ADT·fold/unfold 등 개념 → 짧은 변환 문제
3. **1+2 연결 리뷰**: 콘테스트는 C++이나 Python으로 풀고, 끝난 뒤 함수형으로 재작성하며 리뷰합니다.
   - 변환 예: DP → 점화식 + fold/scan, 그래프 탐색 → 상태 전이 함수 + unfold, 세그트리 → 모노이드
   - 리뷰 질문: "상태와 전이는 무엇인가? 이 루프는 어떤 fold인가? 불변식은?"
4. **현대 디자인 패턴**: functional core/imperative shell, 명세(타입·테스트)를 에이전트와의 계약으로 쓰기, eval-driven development, 데이터·모델·프롬프트 버전 관리, 작은 diff와 관측 가능성. 학습은 케이스 스터디와 리팩터링 실습으로 진행합니다.

## 6. 동기부여 · 몰입 환경 (신규)

### 6.1 이론적 기반
- **자기결정성 이론**(Deci & Ryan): 지속되는 내적 동기는 **자율성·유능감·관계성** 세 가지에서 나옵니다. 모든 장치를 이 셋 중 하나에 연결합니다.
- **몰입(Flow)**(Csikszentmihalyi): 명확한 목표, 즉각적 피드백, 도전-기술 균형이 조건입니다. 85% 규칙과 짧은 제한시간이 이 조건을 시스템적으로 만족시킵니다.
- **목표 설정 이론**(Locke & Latham): 구체적이고 도전적인 목표가 모호한 목표("열심히")보다 성과가 높습니다.
- **진척의 원리**(Amabile): 작은 전진을 **눈으로 확인할 때** 동기가 가장 크게 올라갑니다.

### 6.2 설계 요소
| 장치 | 근거 | 구현 |
|---|---|---|
| **성장 가시화** | 유능감, 진척 원리 | 스킬 태그별 레이팅 그래프. Woodpecker 회차별 소요 시간 PR. "3주 전엔 못 풀던 문제" 리플레이 |

| **선택권** | 자율성 | 다음 세션 후보 2–3개를 제시(예: 약점 집중 / 신규 개념 / 스피드런). 강제 경로 없음 |

| **관계성** (선택) | 자기결정성 | 스터디 파트너, 주간 기록 공유, 서로 문제 출제. 혼자 써도 되는 옵션 |

### 6.3 연구상 피해야 할 것 (반영해서 제외)
- **보상 남발**(포인트, 배지, 상품): 외적 보상은 내적 동기를 깎을 수 있습니다(과잉정당화 효과, Deci et al. 1999 메타분석). 배지는 "실제 실력 이정표"에만 붙입니다.
- **잃으면 끝나는 스트릭**: 불안을 유발하고, 끊기면 이탈로 이어집니다. 주 단위 목표 + 휴식권(streak freeze)으로 대체합니다.
- **낯선 사람과의 리더보드**: 하위권의 동기를 떨어뜨립니다. 기본값은 "과거의 나"와의 비교입니다.
- **가변 보상 / 도박형 장치**: 단기 참여는 올리지만 학습과 무관한 행동을 강화하므로 쓰지 않습니다.
- **마인드셋 메시지에 의존**: 성장 마인드셋 개입의 효과는 메타분석상 작습니다(Sisk 2018). 문구보다 실제 성장 데이터를 보여주는 쪽이 낫습니다.

### 6.4 "성과 ≠ 학습"을 미리 알려주기
- 교차 학습과 간격 반복 같은 바람직한 어려움은 **당장의 정답률을 떨어뜨리지만** 장기 실력은 올립니다(Soderstrom & Bjork 2015).
- 이걸 모르면 "요즘 더 못하는 것 같다"는 느낌에 이탈합니다.
- 그래서 대시보드에 **세션 정답률(단기)과 장기 유지율·레이팅(장기)을 분리**해서 보여주고, 그 이유를 짧게 설명합니다.

## 7. 모바일 스낵 창구
- **PWA**로 만들어 오프라인에서도 쓸 수 있게 합니다.
- 한 번에 1–3분: FSRS 복습 + 전술 퍼즐 3개 + 코딩 미니 문제(출력 예측 / 복잡도 맞히기 / 버그 찾기)
- 레이팅과 FSRS 상태는 데스크톱과 공유합니다. 긴 문제는 데스크톱 전용입니다.
- 스낵 세션은 §6.2의 "실행 의도" 알림과 연결해 일상 틈새에 습관으로 붙입니다.

1. **M1 엔진**: 데이터 모델, FSRS, Glicko-2, 타이머
2. **M2 체스 전술 팩**: Lichess 퍼즐 DB 임포트, 스피드/정확도 모드, 모바일 PWA, 성장 가시화 대시보드
3. **M3 코딩 팩**: CF 메타데이터, 기법 카드, 함수형 재작성 리뷰 템플릿
